# AGENTS.md - 個人筆記整理網站專案規範

本專案為一個極簡、無框架的「個人筆記整理網站」，主要託管於 GitHub Pages。此文件為 AI 代理人（以及開發者）在協助維護、新增與修改本專案時必須嚴格遵守的最高指導原則。

---

## 1. 專案目的與核心精神

- **專案目的**：提供使用者一個簡潔、直覺、好閱讀的個人知識與筆記整理平台。
- **核心架構原則（一個主題一篇）**：
  - **嚴格落實「一個主題一篇筆記」**。
  - 同一主題的所有知識點、延伸內容與後續補充，皆必須收斂整併在同一個主題檔案中，嚴禁因為多次輸入而零碎建立多個重複或相近主題的散亂筆記。

---

## 2. 運作方式

1. **純靜態客戶端架構**：
   - 無需任何後端伺服器（Serverless / Static Hosting）。
   - 筆記內容以獨立的標準 Markdown（`.md`）檔案存放在 `notes/` 資料夾中。
2. **動態載入與渲染**：
   - 瀏覽器開啟 `index.html` 時，透過原生 JavaScript 讀取 `notes/index.json`（筆記清單索引）。
   - 左側側邊欄列出所有主題與標籤分類。
   - 使用者點選側邊欄主題時，前端以 `fetch` 異步取得對應的 `.md` 檔案，並透過輕量 Markdown 解析器（如 marked.js CDN）即時渲染至右側閱讀區。
3. **即時檢索與切換**：
   - 支援側邊欄即時主題點擊切換，閱讀體驗流暢不需重新整理全頁。

---

## 3. 技術限制

- **禁止使用任何前端框架**：
  - 嚴格禁止使用 React、Vue、Angular、Svelte、Next.js 等重型或需編譯之框架。
  - 必須採用 **原生 Vanilla Web 技術**：原生 HTML5、CSS3、現代原生 JavaScript (ES6+)。
- **GitHub Pages 相容相容性**：
  - 所有資源引用、連結、CSS/JS 與 Markdown 載入路徑均必須採用 **相對路徑**（Relative Paths）。
  - **零建置步驟（No Build Step）**：不需要 `npm run build`、`webpack` 或 `vite` 打包，推送到 GitHub 倉庫即可直接經由 GitHub Pages 呈現。

---

## 4. 檔案結構與命名規範

```text
personal-notes/
├── AGENTS.md              # AI 與專案開發維護規範（本檔案）
├── index.html             # 網站單一主入口頁面（包含側邊欄與閱讀容器）
├── css/
│   └── style.css          # 全域樣式與 Notion 極簡風格設定
├── js/
│   └── app.js             # 筆記索引讀取、Markdown 解析、切換與互動邏輯
├── notes/                 # 筆記儲存專用目錄
│   ├── index.json         # 筆記清單索引（管理所有主題中繼資料）
│   └── example-topic.md   # 各主題獨立 Markdown 筆記
└── assets/                # 靜態圖片或圖示資源（若有）
```

### 檔案命名規範：
- 筆記 Markdown 檔案：一律採用英文字母小寫、連字號（kebab-case），例如：`docker-guide.md`、`git-workflow.md`、`frontend-basics.md`。
- 程式碼與樣式檔案：結構簡潔明瞭，一律保持全小寫。

## 5. 新增筆記的固定格式

每篇新增或維護的 Markdown 筆記均必須遵循以下標準結構：

```markdown
# [主題名稱]

> 📅 **建立日期**：YYYY-MM-DD ｜ 🔄 **最後更新**：YYYY-MM-DD  
> 🏷️ **標籤**：`#標籤1` `#標籤2`  
> 📝 **核心摘要**：用 1~2 句話精確總結本主題的核心主旨。

---

## 1. 核心概念與概述

（此處填寫主題的基礎定義或重點）

## 2. 詳細內容與知識重點

（結構化條列具體內容、步驟或程式碼區塊）

## 3. 常見問題與注意事項

（補充容易混淆的細節、踩坑紀錄或常見問題）
```

## 6. 資料處理原則（最高準則）

1. **只整理使用者給的資料（嚴禁自行腦補）**：
   - AI 在整理或新增筆記時，**僅能依據使用者明確提供的內容、重點與文字**進行結構化梳理。
   - **嚴禁自行發明、杜撰、腦補未提供的外部資訊或技術細節**。若資訊不足，應在文末標註「待補充」或直接向使用者詢問。
2. **同主題合併原則（Strict Topic Merging）**：
   - 當使用者提供新資料時，AI 必須**先檢索既有筆記**（查閱 `notes/index.json` 或現有檔案）。
   - 若已有相同或高度重疊的主題：
     - **絕對禁止建立新的重複檔案**。
     - 必須讀取現有筆記，將新資料合理整合、擴充至對應章節中。
     - 同步更新該筆記開頭的「🔄 最後更新：YYYY-MM-DD」日期。
   - 若為全新獨立主題：
     - 方可按照固定格式建立新的 `.md` 檔案，並同步在 `notes/index.json` 中註冊該筆記。

## 7. 視覺風格（Notion 極簡風）

- **色彩與氛圍**：
  - 背景採用溫和純淨的白底或淡米灰底色（`#ffffff` / `#fbfbfa` / `#f7f6f3`）。
  - 文字主色採用高質感暗灰（`#37352f`），輔助文字與中繼資料採用次級灰（`#787774`）。
- **字體與排版**：
  - 優先採用系統無襯線字體（Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "PingFang TC", "Microsoft JhengHei", sans-serif）。
  - 行高保持舒適的 `1.65` ~ `1.75`，段落間距適中。
- **介面佈局**：
  - **左側側邊欄**：展示個人筆記網站名稱、簡潔的主題列表，點擊項目有微質感的 Hover 與 Active 背景色變化。
  - **右側閱讀區**：寬度限制在舒適閱讀寬度（約 760px ~ 880px 置中），呈現如同在 Notion 頁面中閱讀的沉浸感。
  - **區塊元素**：引用區塊（Blockquote）、程式碼區塊（Code Block）、表格均需具備圓角（Border-radius）與柔和背景色。

## 8. AI 修改規則與完成檢查清單

### AI 執行任務規則：
1. **先查後動**：在進行任何筆記新增或修改前，先檢查現有主題，落實同主題合併原則。
2. **不擅自建立多餘檔案**：嚴格依照既定目錄結構維護，不建立未經同意的構建腳本、套件設定檔等。
3. **相對路徑保護**：任何引用的連結與靜態資源，確保在 GitHub Pages 的二級路徑或根目錄下皆能正常解析。

### 完成檢查清單（Checklist）：
在交付任何修改或回答使用者前，AI 必須逐一核對：
- [ ] 是否維持「一個主題一篇」，無碎片化或重複主題檔案？
- [ ] 筆記內容是否嚴格限定於使用者給予的資料，無未經證實的自行腦補？
- [ ] 筆記若為舊主題增補，是否已更新「最後更新日期」？
- [ ] 若有新增筆記，是否已同步將新主題登錄於 `notes/index.json`？
- [ ] 程式碼與網頁結構是否維持原生無框架，並確保能在 GitHub Pages 正常運作？
